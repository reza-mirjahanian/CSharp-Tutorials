# Understanding `using System;` and Hidden Imports in .NET

In older C# code, you often see this line at the top of the file:

```csharp
using System;
```

This imports the **`System` namespace**, which contains many fundamental .NET types, including `Console`.

Because of that import, this statement works:

```csharp
Console.WriteLine("Hello, World!");
```

Without access to the `System` namespace, you would normally need to write the full name:

```csharp
System.Console.WriteLine("Hello, World!");
```

---

# 🧠 Why Does `Console.WriteLine` Work Without `using System;`?

In modern .NET projects, especially .NET 6 and later, you might not see this line:

```csharp
using System;
```

Yet this still works:

```csharp
Console.WriteLine("Hello, World!");
```

That happens because the import is being added **automatically** for you.

> You still need the `System` namespace.  
> You just do not always have to write `using System;` manually anymore.

This is done through two modern features:

1. **Global using directives**
2. **Implicit using directives**

---

# 🌍 Global Using Directives

A normal `using` directive applies only to the file where it appears.

Example:

```csharp
using System;

Console.WriteLine("Hello");
```

But a **global using** applies to the whole project.

Example:

```csharp
global using System;
```

This means every `.cs` file in the project can use types from `System` without writing `using System;` at the top.

---

# ⚙️ Compiler-Generated Global Usings File

For projects targeting .NET 6 or later, the compiler can automatically generate a file containing common global imports.

This file is usually located inside the `obj` folder.

Example path:

```text
obj/Debug/net10.0/HelloCS.GlobalUsings.g.cs
```

The exact path depends on:

- your project name,
- build configuration,
- target framework.

For example:

```text
obj/Debug/net8.0/MyProject.GlobalUsings.g.cs
obj/Release/net10.0/HelloCS.GlobalUsings.g.cs
```

---

# 📄 Example: `HelloCS.GlobalUsings.g.cs`

The generated file may look like this:

```csharp
// <autogenerated />
global using System;
global using System.Collections.Generic;
global using System.IO;
global using System.Linq;
global using System.Net.Http;
global using System.Threading;
global using System.Threading.Tasks;
```

These imports are automatically available throughout the project.

---

# 🧩 What Each Global Import Gives You

| Global Import | Common Types It Provides |
|---|---|
| `System` | `Console`, `Exception`, `String`, `DateTime`, `Math` |
| `System.Collections.Generic` | `List<T>`, `Dictionary<TKey, TValue>` |
| `System.IO` | `File`, `Directory`, `StreamReader` |
| `System.Linq` | LINQ methods like `Where`, `Select`, `OrderBy` |
| `System.Net.Http` | `HttpClient` |
| `System.Threading` | `Thread`, `CancellationToken` |
| `System.Threading.Tasks` | `Task`, async programming types |

---

# 🗂 Finding the Generated Global Usings File in Visual Studio

To view the generated file:

1. Open **Solution Explorer**.
2. Click **Show All Files**.
3. Expand:

   ```text
   obj
   ```

4. Expand your build configuration folder, such as:

   ```text
   Debug
   ```

5. Expand your target framework folder, such as:

   ```text
   net10.0
   ```

6. Open the file named something like:

   ```text
   HelloCS.GlobalUsings.g.cs
   ```

---

# 👁 Hiding Generated Files Again

After viewing the generated file, you can hide the `bin` and `obj` folders again.

In **Solution Explorer**, toggle off:

```text
Show All Files

This hides files and folders that are not usually edited directly.

```

# ⚠️ Important: Do Not Edit `.g.cs` Files

Files ending in `.g.cs` are generated files.

Example:

```text
HelloCS.GlobalUsings.g.cs
```
The `g` means **generated**.

> Generated files are created automatically by the compiler or build tools.  
> If you edit them manually, your changes may be overwritten the next time the project builds.

You should edit your own files instead, such as:

```text
Program.cs
HelloCS.csproj
```

# 🧱 Normal `using` vs. `global using`

## Normal `using`

Applies only to one file:

```csharp
using System;

Console.WriteLine("Hello");
```
If another file needs `System`, it must also import it unless global usings are available.

---

## Global `using`

Applies to the entire project:

```csharp
global using System;

Now all files in the project can use `Console`, `Exception`, and other `System` types.

```

# 🆚 Comparison Table

| Feature | Scope | Example |
|---|---|---|
| Normal `using` | Current file only | `using System;` |
| Global `using` | Whole project | `global using System;` |
| Implicit using | Added automatically by SDK | Generated in `obj` folder |

# 🛠 Why Modern Console Apps Look So Small

A modern .NET console app might only contain:

csharp
Console.WriteLine("Hello, World!");

But several things are happening behind the scenes:

1. The compiler provides the hidden `Program` class.
2. The compiler provides the hidden `<Main>$` method.
3. The project SDK provides common namespace imports.
4. `System` is imported globally.
5. `Console.WriteLine` becomes available automatically.

So this simple code:

```csharp
Console.WriteLine("Hello, World!");
```
is supported by hidden generated code and project settings.

---

# 🧨 Revealing Hidden Code by Throwing an Exception

You can reveal some of the hidden top-level program structure by deliberately throwing an exception.

Start with a simple `Program.cs` file:



```csharp
Console.WriteLine("Hello, World!");

throw new Exception();

```

# ▶️ Running Without Debugging

In Visual Studio, run the application using:

```text
Debug → Start Without Debugging
```
Do **not** use normal debugging mode for this demonstration.

> If you start with debugging, Visual Studio may catch the exception before the console output shows the full runtime error details clearly.

---

# 💥 Example Exception Output

The console output may look similar to this:

```text
Hello, World!
Unhandled exception. System.Exception: Exception of type 'System.Exception' was thrown.

```
The exact file path and line number will be different on your machine.

---

# 🔍 What the Exception Output Reveals

This part is especially important:

```text
at Program.<Main>$(String[] args)
```
It shows that the compiler generated:

| Hidden Item | Meaning |
|---|---|
| `Program` | The hidden class created by the compiler |
| `<Main>$` | The hidden entry-point method |
| `String[] args` | The command-line arguments parameter |

---

# 🧠 Understanding `<Main>$`

When you use top-level statements, you do not write this:

```csharp
class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("Hello, World!");
    }
}
```
But the compiler creates something similar internally.

The generated method is named:

```text
<Main>$
```
This name is used by the compiler for the hidden entry point.

---

# 🧪 Top-Level Code Example

Your visible code:

```csharp
Console.WriteLine("Hello, World!");

throw new Exception();
```
Conceptually behaves like:

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        Console.WriteLine("Hello, World!");

        throw new Exception();
    }
}
```
The actual compiler-generated details may differ, but this gives the correct mental model.

---

# 📌 Key Hidden Features in Modern .NET Console Apps

| What You Write | What .NET/C# Provides |
|---|---|
| `Console.WriteLine("Hello");` | Global import for `System` |
| No `using System;` | Generated global using directive |
| No `Program` class | Hidden `Program` class |
| No `Main` method | Hidden `<Main>$` method |
| No `string[] args` | Hidden `args` parameter |

---

# 🧾 The Role of the Project Template

Modern .NET project templates intentionally hide boilerplate code.

A new console app may look like this:
```csharp
Console.WriteLine("Hello, World!");
```
But the project is still using:

- namespaces,
- imports,
- classes,
- an entry point,
- command-line arguments,
- generated files.

They are just handled automatically.

---

# ⚙️ Why This Changed in .NET 6

In .NET 6 and later, many project templates were updated to use newer C# features by default.

These include:

- **top-level statements**
- **global using directives**
- **implicit using directives**
- **simplified project files**

This makes beginner projects shorter and easier to read, while still allowing advanced developers to use the full explicit style when needed.
